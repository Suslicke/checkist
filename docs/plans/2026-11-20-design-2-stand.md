# Стенд для снимков Чекиста 2.0 (2026-11-20, ветка `feature/design-2`)

Одноразовый локальный стенд для тех, кто переписывает клиент на новую дизайн-систему
([2026-11-20-design-2.md](2026-11-20-design-2.md)): настоящий Django/DRF + Vite dev (горячая перезагрузка рабочего
дерева `frontend/`), PostgreSQL с богатыми **вымышленными** данными и скрипт снимков через headless Chrome. Прод не
трогается, модели ИИ не вызываются (все провайдеры — `fake`). Файлы стенда лежат вне репозитория:

## Команды

```bash
. $STAND/env.sh                 # окружение стенда (fake-провайдеры, порты, база)
$STAND/start.sh                 # поднять всё, что не запущено (идемпотентно)
$STAND/stop.sh                  # остановить всё; база и MEDIA остаются
$STAND/seed.sh                  # пересоздать базу с нуля: dropdb → createdb → migrate → seed.py → start.sh (~1 мин)
$STAND/api.sh GET /api/dashboard/              # запрос к API от anna (сессия и CSRF внутри)
STAND_USER=boris $STAND/api.sh GET /api/me/    # от boris
```

`seed.sh` можно запускать при работающих Django и Vite (останавливает и перезапускает только воркер). Повтор даёт те же
данные и те же id (генератор с фиксированным зерном). Карта id — `$STAND/ids.json`. Если кто-то в браузере стенда
что-то сохранил или удалил — `seed.sh` возвращает исходное состояние.

## Снимки: `shoot.mjs`

Node ≥ 22, без пакетов (CDP через глобальный `WebSocket`). Входит один раз через API (`/api/auth/csrf/` →
`/api/auth/login/` через 15173), кладёт `sessionid`/`csrftoken` в **свой** контекст браузера (запуски разных агентов
не мешают друг другу), на каждый снимок — новая вкладка.

```bash
node $STAND/shoot.mjs --routes "/,/receipts,/receipts/58" --widths 390,1280 --themes light,dark \
     --platforms ios,android --out $STAND/shots/<папка> [--full]
node $STAND/shoot.mjs --routes-file $STAND/routes.txt --widths 390 --themes light --platforms ios --out $STAND/shots/all
node $STAND/shoot.mjs --guest --routes-file $STAND/routes-guest.txt --widths 390,1280 --out $STAND/shots/guest
```

- Ширина ≤ 600 — телефон: `mobile`, DPR 2, высота 844, касание (`pointer: coarse` = true), UA iPhone/Pixel по
  `--platforms`; шире — компьютер: DPR 1, высота 800, `pointer: fine`.
- Перед загрузкой страницы: `localStorage['checkist.theme']` = тема, `localStorage['checkist.platform']` = платформа,
  `prefers-color-scheme` = тема, `prefers-reduced-motion: reduce` (выключить — `--motion`). Свои ключи —
  `--storage "checkist.privacy=1,checkist.listIcons=method"`.
- Готовность: `document.readyState === 'complete'`, в `#root` что-то есть, нет `[aria-busy="true"]` и `.ck-skel`
  (не дольше `--timeout`, 15 с), потом `--settle` (400 мс).
- Файл: `<out>/<slug>-<ширина>-<тема>-<платформа>.png`, slug — путь без `/` (`/` → `home`, `?a=b` → `_a_b`).
- Строка на снимок: `ok`/`SLOW`, имя файла, `OVERFLOW sw>iw` при прокрутке вбок, `coarse=`, число ошибок консоли, `h1`,
  `landed=` если адрес сменился; ниже — сами ошибки (console.error, исключения, 4xx/5xx ресурсов).
- `--full` снимает всю страницу (`captureBeyondViewport`); фиксированные элементы (нижнее меню, «＋») при этом остаются на
  месте первого экрана, а не внизу страницы — так у любого полностраничного снимка Chrome.
- `--user`/`--password`, `--base` (по умолчанию http://127.0.0.1:15173), `--cdp` (http://127.0.0.1:9222), `--height`.
- Все 62 адреса × 1 вариант ≈ 65 с.

## Известное

- `/health` — сбои Redis/Celery (их на стенде нет); на `/account` в консоли 404 `/api/auth/pocket-id/` (Pocket ID не
  настроен), у гостя — 401 `/api/me/`: это не ошибки клиента.
- Чеки с настоящей картинкой — только немецкие (fake-распознавание другого не выдаёт), с переводом в тенге по курсу.
- Уведомления: ключей VAPID нет — блок пишет «не настроено на сервере».
- Работающий fake-воркер обрабатывает всё, что загрузят или спросят на стенде (сценарий фото — `one_receipt`, чат —
  `chat`); настоящие модели не вызываются (`RECEIPT_OCR_*_EXECUTABLE` указывают на несуществующие файлы).
- Стенд держит Postgres/Django/Vite/Chrome часами; после работы — `$STAND/stop.sh`. Каталог scratchpad может очиститься
  перезагрузкой — тогда стенд собирается заново по этому файлу и рецепту `initdb` из `$STAND/env.sh`.
